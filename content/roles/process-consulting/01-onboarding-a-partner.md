# Onboarding a Partner

Onboarding splits across three roles. Once every subtask below is marked
complete across all three, ClickUp automatically moves the partner to
**Active**.

| Task | Owner |
|---|---|
| Client kickoff call | Process Consultant |
| Async update after the kickoff call | Process Consultant |
| Engineering handover document | Process Consultant |
| Post-kickoff NPS form | Process Consultant |
| Confirm the call is scheduled, send the Slack invite, save the recording | Project Manager |
| Financial tracking | Operations Manager |

## Conducting the client kickoff call

The client-facing centerpiece of onboarding: rapport, a roadmap recap,
minimum and maximum success criteria, blocking dependencies, and a close
that sets up the onboarding document. Run it in this order.

| Step | What to do |
|---|---|
| 1. Set up | Confirm it's being recorded, usually via Fathom. Have the onboarding document open. |
| 2. Introductions | Go around both teams. Name anyone new or shadowing. |
| 3. Set the agenda | State the call's purpose and how much time is available. Name anything stuck in email or Slack so it resolves live. |
| 4. Recap the roadmap | Share what's done and what's next (interviews, surveys, deliverables). Confirm point of contact, what's scheduled, what's pending. |
| 5. Confirm interview logistics | Number and structure of interviews or surveys, who's included, any client review step. State what the client gets back: raw data or a summarized analysis. |
| 6. Define minimum success | Ask: "I would be disappointed if we did not at least ___." Be explicit about scope, this phase or the whole engagement. No wrong answer. |
| 7. Define maximum success | Ask: "You would tell everyone about us if we achieved ___." |
| 8. Probe and clarify | Pin down vague answers: who it applies to, what the output looks like, current phase or full partnership. Address framing concerns directly. |
| 9. Surface blocking dependencies | Name IT/security approval, data access, or a missing stakeholder as a dependency. State the timeline impact if it isn't resolved. |
| 10. Clarify end state | Who the final readout goes to, in what format, by whom. |
| 11. Recap next steps | Restate the sequence. Resolve scheduling conflicts live where possible. |
| 12. Close | Thank the client, confirm any follow-up meetings, fill out the onboarding document live or immediately after. |

## Filling out the onboarding document

The onboarding document is the single source of truth on a client's
business, workflows, stakeholders, and goals. Find it in ClickUp under
**Partner Fulfillment → the partner's folder → Resources →
"Kickoff Document | Partner Name."**

<Figure id="pc-onboarding-doc-template" caption="The onboarding document template, blank, opened to the top section" spec="ClickUp, Partner Fulfillment, the partner's Resources folder, blank Kickoff Document template, full page" />

Fill it out to recreate a clear picture of the client's world as described on
the call:

- Company name and niche
- Departments and stakeholders
- Pain points
- Definition of success
- Company goals
- Company tech stack
- Call schedules
- Notes

Once it's ready for review, drop a message in the relevant ClickUp channel.
It feeds the Scope of Work, kickoff decks, ClickUp definitions of success,
and implementation milestone planning.

<Callout>A thin onboarding doc becomes a scoping problem two weeks later.</Callout>

## Creating the engineering handover document

Once the kickoff call outcomes are clear, turn that context into a document
engineering can start from without chasing you down.

| Step | What to do |
|---|---|
| 1. Gather source material | The signed SOW (scope, deliverables, timeline) and the kickoff call recording or transcript. |
| 2. Thought vomit into Claude, same day | Dump everything relevant in whatever order it comes out: what the client cares about, tone and personality notes, technical constraints, timeline pressure, anything unusual. |
| 3. Add the SOW and the kickoff call to the same conversation | The SOW keeps the handover grounded in what was actually contracted. The call carries the client's own language. |
| 4. Run the Engineering Handover skill | Review the output against the real scope and specifics from this call, not generic templated language. |
| 5. Post it to the designated ClickUp channel | Tag the relevant engineering lead so they're notified it's ready. |
| 6. Stay available for follow-up | Route engineering's clarifying questions to yourself, not back to the client. |

<Callout>A rushed thought vomit, or a handover built without the SOW in the loop, is the most common way scope gets misread before work even starts.</Callout>

Once the kickoff call, async update, engineering handover, and post-kickoff
NPS form are done, and the Project Manager's and Operations Manager's
onboarding subtasks are too, the partner moves to Active automatically.
